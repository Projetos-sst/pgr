# Mapeamento de QA — sst-manager

> Documento de apoio para uma futura rodada de **QA abrangente**: mapeia todas as issues
> do projeto (o que cada uma é + os principais pontos de regra de negócio a validar),
> agrupadas por fase. A ideia é servir de checklist para revisar se tudo está de acordo
> com as regras de negócio antes de considerar cada entrega concluída.
>
> **Escopo:** este arquivo é só o mapeamento. Os casos de teste detalhados (passos,
> dados, resultado esperado) ficam para uma etapa posterior.

## Como ler

- **Status** reflete o estado da _issue_ no GitHub, não a coluna do board:
  - `✅ Fechada` — issue encerrada (em tese implementada e mergeada → **candidata a QA agora**).
  - `🔎 Aberta` — issue ainda aberta (em revisão / a implementar).
- **O que é** — resumo de 1 frase do objetivo da issue.
- **Regras de negócio a validar em QA** — 2 a 4 pontos testáveis por issue, com foco em
  regra de negócio real (isolamento multi-tenant, validações, unicidade, transições de
  status, cálculos, permissões `owner`/`collaborator`/`client`).

a dados passa por `withOrg(orgId, …)` (fixa `app.current_org`) + backstop de RLS no banco;
